# Iterative implementation

Use a short plan, implement one meaningful slice at a time, inspect the result, and correct gaps against the acceptance criteria. Keep a compact progress note when the work spans multiple stages.

- Set a concrete completion condition before the first edit. Reuse the user's criteria when present.
- Reassess after each slice; do not repeat a pass that produced no new evidence.
- Stop when the criteria are met, after six meaningful iterations, or when a blocker requires user input. Report which condition ended the cycle.
- Run validation only when requested or required by the task's acceptance criteria. Do not commit, push, or open a PR unless asked.
