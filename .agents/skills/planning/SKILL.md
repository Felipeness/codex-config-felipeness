# Planning

- Turn the request into outcomes, constraints, and acceptance criteria. Reuse available product and repository context before asking questions.
- Compare only the options that could materially change the result. Include operational cost, reversibility, failure modes, and migration impact.
- Recommend a smallest useful approach and list the main steps, dependencies, and decision points.
- Mark assumptions explicitly. Ask only for decisions that block safe progress; otherwise choose a reversible default and proceed when implementation is requested.
- Keep the plan proportional to the task. Do not create a design document unless it is useful or requested.
