# Code review comments

- State the issue and its consequence plainly; avoid sarcasm, blame, or performative praise.
- Explain the triggering case or invariant that fails. Suggest a concrete direction when it helps.
- Keep each comment focused on one concern and use questions only when the design intent is genuinely unknown.
- Distinguish blocking defects from optional improvements. Avoid stating preference as a requirement.
- Draft comments by default. Post them only when the user asks for that external action.
