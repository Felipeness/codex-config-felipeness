# Technical writing

- Identify the reader and the action the text should enable. Put the useful information first and use concrete language.
- Match the repository's language and style. For this configuration, use Brazilian Portuguese in user-facing docs by default and English for code identifiers.
- Keep claims aligned with implementation. Verify paths, commands, defaults, and compatibility notes in source before documenting them.
- Use examples that are safe to copy. Mark placeholders clearly and never include real secrets.
- For commit or PR text, summarize behavior and rationale; include validation only when it was actually performed.
