# Iterative test development

- Translate the requested behavior into a small set of observable cases, including important failure paths.
- Inspect test conventions and available commands before adding files.
- Add the most valuable test first, run the requested targeted command, and adjust either the test or implementation based on evidence.
- Stop when the requested cases pass or after six meaningful iterations. Do not widen into unrelated coverage or run the full suite unless requested or required.
