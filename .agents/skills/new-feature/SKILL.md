# New feature

- Inspect the current architecture and related behavior first. Identify the smallest change that satisfies the requested outcome.
- For substantial work, outline affected areas, behavior, edge cases, and acceptance criteria before editing. For a small, clear task, proceed directly.
- Follow local patterns and reuse existing interfaces. Surface a genuine product or compatibility decision before committing to an irreversible direction.
- Implement in cohesive steps and keep documentation aligned with user-visible behavior.
- Choose verification that matches the requested acceptance criteria and repository conventions. Report what changed and any unverified assumptions.
- Do not publish, push, or open a PR unless the user asks for that action.
